# 独立钉钉通知应用实施计划

**目标：** 保留现有工作台登录，使用另一个组织的独立机器人发送已经核验的个人通知；群接收条件不满足时明确停用群通道。每天15:30整理、目标16:30前发送曾悦专报，失败即时提醒李睿琪并在16:50兜底。

**已批准范围：** 用户2026-10-18明确要求核对后直接接入、恢复每日通知和17:00前失败提醒。保留原卡片和业务权限，图片推送保持关闭。当前办公群跨组织核验被拒绝，不能宣称群发恢复。

**结构：** 新增 `app/notification_transport.py` 读取固定私有通知配置并校验企业、应用、固定实名账号和人员路由。`app/dingtalk_notifications.py` 按已启用通道发送，`app/notification_cards.py` 使用独立本人路由；旧登录绑定校验路径保持。应用凭据和接收标识不得进入源码。

- [ ] 为独立应用、停用群、企业不匹配、非固定账号和停用账号编写合成测试。
- [ ] 实现固定私有配置读取和按通道发送，保持防重、旧日报拦截、PDF鉴权及失败后不回滚业务。
- [ ] 启用已经核验的曾悦专报和李睿琪异常提醒，原办公群保持关闭。恢复原每日自动化的通知指令，启用16:50静默任务。
- [ ] 更新V0.3.22及变更记录，运行必要测试、实际服务检查，保留旧版。

**验收：** 无跨企业身份混用，不能借通知配置更改登录账号权限；不自动重发未知结果；不可用群通道在状态中显示停用；曾悦测试有平台回执，本人通道已在客户端实收；自动化恢复原15:30周期，兜底任务16:50；私有配置不在Git跟踪范围。
