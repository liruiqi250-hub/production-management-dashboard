# 钉钉办公群日报与曾悦专报实施计划

> 执行方式：本会话按步骤实施并逐项验证，不委派其他会话。用户已确认接收范围和内容，沿用既有账号与业务规则。

**目标：** 每天15:30既有整理任务成功后、目标16:30前，将简明日报发送到钉钉办公群，将重点问题、逾期及协调事项单独发送曾悦。

**架构：** 标准库实现企业应用机器人消息适配；每日完成任务生成固定接收目标的本地发件箱，按日期、消息类型及目标防重。已发送不重发；网络结果不确定时保留待核状态，不自动重复。钉钉配置、接收者ID、消息正文和发送日志仅留private。仅成功且日期正确的已发布快照可发送。

**技术栈：** 现有 Python/SQLite、钉钉企业机器人 OpenAPI、现有 Codex 每日自动化与后台 app.jobs；不引入新的通用运行依赖。

## 实施清单

- [ ] 核验企业机器人配置与消息权限、办公群唯一身份及曾悦本人企业身份；不按近似群名猜测，不改其他已授权权限。
- [ ] 新增 app/dingtalk_notifications.py：确定性短摘要、已登记范围、工厂三天优先规则、生产与售后合并计数、只读看板链接、不复制微信原文；通道与每日发件箱防重、状态查询与明确补发。
- [ ] 新增 tests/test_dingtalk_notifications.py：关闭/无配置不发送、目标固定、完成后触发、当日/迟到/旧数据边界、幂等与并发、明确拒绝可重试、超时待核不重发、群/领导内容差异、个人权限与待并案统计。
- [ ] app/jobs.py 在日报周报归档成功后调用推送；消息失败不回滚已更新台账，在任务状态保留推送结果。终端支持预览/状态/只重试明确失败，不能通过网页传入任意接收者。
- [ ] 更新 automation/每日集中整理.md 及既有15:30自动任务提示，保留每天周末运行、理解手册与法定放假计时规则，不另建重复采集任务。
- [ ] 现场配置与一轮明确标注的连通测试，核验办公群和曾悦实际接收、链接打开、发送结果与防重。首次真实日报使用当日成功整理产物，不发送过期日报。
- [ ] 更新 V0.3.20 所有版本入口与说明，保留 V0.3.19。完整回归、保护表校验、清洁GitHub发布、full-wechat便携包及8项Release附件校验。

## 验收边界

软件具备消息能力、后台保存机器人、API接受、实际收到、次日定时发送分别记录证据。不能把开发完成或接口返回成功当作已收消息；不承诺办公室关机、采集未完成时仍能按时生成新日报。
