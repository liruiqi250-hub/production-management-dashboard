# V0.3.32 电脑钉钉授权返回修复

## 已确认的问题

曾悦电脑钉钉显示 V0.3.31 的“未能确认钉钉身份”，点击下方钉钉登录仍未恢复。当前这句文案只对应原生 SDK 获取授权码失败，尚未调用服务端免登身份交换，不能据此认定账号绑定或权限错误。

另一个可由源码确认的问题是：网页 OAuth 返回后，再次无条件执行工作台免登；原生接口不可用时会重新失败，原生 start 还会取消刚建立的首次绑定临时状态。已有后端模拟测试没有覆盖前端这段返回流程。

## 修复边界

- 保留原生免登、网页 OAuth 和原账号登录；不修改应用凭据、可见范围、已有绑定、权限、12 小时会话与业务数据。
- 仅真实 OAuth 回调验证成功时发出短期 HttpOnly 返回凭据，绑定本次会话或待绑定凭据；由同源状态接口验证签名、时效、对应凭据后消费。前端只接受这一服务端结果，不相信 URL 中的 ok/bind 标记。
- 已完成本次 OAuth 会话验证时进入原 load 流程；首次绑定则保留本人账号及明确勾选确认步骤，不再重复请求原生授权。
- 原生失败保留受限数字诊断码和中文恢复指引，不显示原生错误原文、授权码、密钥或个人资料；同一个按钮明确可改用网页授权。

## 验收

1. 备份 V0.3.31 及真实库，保护账号、绑定和人工结果。
2. 覆盖签名伪造、过期、未来时间、跨会话、跨绑定、重放及 URL 伪造；保留原 nonce、Origin、停用账号和权限回归。
3. 直接执行实际前端函数，覆盖原生成功/拒绝/超时/组件缺方法，以及 OAuth 已绑定/首次绑定返回。
4. 用隔离临时库和模拟钉钉 UA，实际检查电脑/手机错误状态、网页授权返回和首次绑定表单。模拟环境不能代替曾悦电脑钉钉的真实登录验收。
5. 同步 V0.3.32 版本、资源参数、入口及日志，保留上一版本。核对 PID 后更新本机服务，核验本机及公网资源；本轮不自动发布 GitHub。
