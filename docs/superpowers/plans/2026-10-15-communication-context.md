# 本机沟通理解资料接入计划

目标：按用户已确认的办公室沟通语境理解简短放行、实际进展和完成范围，让每次自动整理都读取本机已核查资料。

方案：聊天原件、个人身份映射和历史案例只存 private。增加固定路径、体积和结构受限的资料读取器；将简明规则与案例作为 DATA 的辅助资料传入现有无工具分析器。历史案例不能成为本轮业务证据，既有来源定位验证及人工结果保留机制继续适用。没有资料时兼容现有整理；非法资料报错，保留正式台账。

- [ ] 新建 app/communication.py，读取 private/communication_profiles_V1.0.0.json，仅接受schema=1、办公室人员、14个生产来源和限定字段；超过128KiB、错误时间或缺少案例定位拒绝。
- [ ] app/jobs.py 将资料加入每轮 analysis_input；写入本轮私有加载凭据（文件摘要、版本、实际覆盖、规则及案例数量）。固定提示说明：自然放行依据上下文，后工序真实发生支持前工序完成，但不能转为最终质量验收；历史案例不能直接关闭当前事项。
- [ ] 为确有同事项明确提问的简短“好/嗯/OK”允许登记阶段放行；孤立收悉、安排及含糊对象继续拒绝。使用合成来源测试正反例和资料越界、载入持久性，不以真实聊天写测试。
- [ ] 同步0.3.6版本、页面资源版本、说明及新入口；保留0.3.5入口和已发布版本。
- [ ] 运行单元回归和真实私有资料载入检查；复核实际数据库与日报周报；核验本项目服务PID后重启。
- [ ] 代码提交后，经清洁发布脚本推送私有main与v0.3.6；构建完整微信语音ZIP、上传对应Release和准确许可源码，回读远端版本、大小及SHA。

自查：不新增云端训练，不为个人口头习惯赋予更高权限，不扩大日常七天采集范围，不把历史学习量计入每日覆盖，不把办公室跟进人认定为实际制作工人。
