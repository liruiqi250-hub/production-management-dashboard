## NocoBase 核验结论

1. 官方 GitHub 当前稳定版是 **v2.2.23**，2026-10-11 发布；同期 v2.3.0-beta.14 与 v2.4.0-alpha.10 均为预发布。本轮不要用浮动 `latest` 代替锁定版本。[官方发布页](https://github.com/nocobase/nocobase/releases/tag/v2.2.23)
2. 官方现行安装文档要求 Node.js >=22、Yarn 1.22.x，以及 PostgreSQL 10+、MySQL 8.0.17+ 或 MariaDB 10.9+。本机 Node 符合要求，但 Yarn 与数据库尚未就绪。[create-nocobase-app 安装](https://docs.nocobase.com/get-started/installation/create-nocobase-app)
3. Windows 本地开发推荐 WSL 2 + Ubuntu LTS；这属于推荐方案，并非“Windows 原生不能安装”。生产文档也明确允许 Windows Server，建议 Linux 生产服务器。[本地开发环境](https://docs.nocobase.com/ai/local-development-setup)、[系统要求](https://docs.nocobase.com/get-started/system-requirements)
4. 新版 `@nocobase/cli` 2.2.23 的入口调用 `ensureWindowsAdministrator()`；Windows 非管理员直接退出。本机当前会话非管理员，所以不能把新的 `nb init` 当作当前会话已可执行的安装路径。本轮没有设置绕过变量、修改检查代码或提权。[管理员检查源码](https://github.com/nocobase/nocobase/blob/v2.2.23/packages/core/cli/bin/windows-admin.js)、[CLI 入口源码](https://github.com/nocobase/nocobase/blob/v2.2.23/packages/core/cli/bin/run.js)
5. 独立 `create-nocobase-app` 2.2.23 仍可作为另一条官方脚手架路径，未发现相同管理员入口门；但本轮没有实际安装、启动和验收，不能称原生路径已跑通。官方新 CLI 默认内置数据库通过容器创建；在当前没有 Docker 的条件下，还须自行准备数据库。[CLI 初始化参数](https://docs.nocobase.com/api/cli/init)
6. 当前脚手架支持的数据库列表为 postgres、mysql、mariadb、kingbase；依赖模板没有安装 sqlite3。数据库包仍有 SQLite 方言文件和测试配置残留，不足以证明 SQLite 是当前正式安装方案。本轮不把 SQLite 作为 NocoBase 生产数据库推荐。[脚手架数据库参数源码](https://github.com/nocobase/nocobase/blob/v2.2.23/packages/core/create-nocobase-app/src/cli.js)、[脚手架依赖模板](https://github.com/nocobase/nocobase/blob/v2.2.23/packages/core/create-nocobase-app/templates/app/package.json)

官方建议应用本身最低 2 GB 内存、推荐 4 GB；从源码构建预留至少 4 GB 空闲内存，数据库与反向代理另算。npm 实测 `@nocobase/app` 2.2.23 本包解包约 37.9 MB，但它依赖 server/database/preset；server 有 49 个直接依赖，client 有 76 个直接依赖。**不能用 37.9 MB 当完整安装体量**。本轮未解析完整传递依赖树或下载完整环境，完整磁盘占用未实测。[系统要求](https://docs.nocobase.com/get-started/system-requirements)、[官方 app 包元数据](https://registry.npmjs.org/@nocobase%2fapp/2.2.23)

## 后续可执行的 NocoBase 路径

优先路径是准备好 WSL 2/Ubuntu 或独立 Linux 主机，再按官方 Docker + PostgreSQL 文档部署锁定版 2.2.23。涉及 WSL 功能、重启、管理员窗口时需要用户实际操作；本轮未启动这些变更。

如必须继续在 Windows 普通用户目录试运行，可另做隔离实验：官方 PostgreSQL ZIP → 初始化仅监听 127.0.0.1 的专用数据库 → 本项目局部 Yarn 1.22.22 → `create-nocobase-app@2.2.23` 生产依赖 → 初始化 → 启动 → 实测登录与权限。PostgreSQL 官方 Windows 下载页明确提供无安装程序的 ZIP；本轮 HEAD 确认其 16.15 Windows x64 ZIP 返回 HTTP 200，大小 373,254,386 字节。它只是可下载的候选依赖，尚未证明本机运行结果。[PostgreSQL 官方 Windows 页面](https://www.postgresql.org/download/windows/)、[官方链接的 EDB 二进制页面](https://www.enterprisedb.com/download-postgresql-binaries)

## 登录与数据 API 调研

以下是官方文档及 2.2.23 npm 包源码核验，不是本机服务验收结果：

- 登录使用资源动作 `auth:signIn`；携带 `X-Authenticator` 选择认证器，响应提供用户与 token。后续 HTTP 使用 `Authorization: Bearer <token>`。2.2.23 的 BasicAuth 源码以 `account`（用户名或邮箱）或兼容参数 `email`、`password` 验证；不应照抄旧教程中的 `username` 登录参数而不实测。[认证扩展流程](https://docs.nocobase.com/auth-verification/auth/dev/)、[官方 auth 包 2.2.23](https://registry.npmjs.org/@nocobase%2fplugin-auth/2.2.23)
- 记录操作采用 `<资源名>:list/create/update/get/destroy`。官方 CLI 可使用 `nb api resource create --resource <名称> --values <JSON>`，批量创建接受 JSON 对象数组；更新以 `--filter-by-tk` 或 `--filter` 定位。[创建 API](https://docs.nocobase.com/api/cli/api/resource/create)、[更新 API](https://docs.nocobase.com/api/cli/api/resource/update)
- CLI 的 `--role` 会发送 `X-Role`。它表示用户当前角色，不等于任意用户都能提升到指定角色；服务端角色归属和权限仍须实测。[通用 API 参数](https://docs.nocobase.com/api/cli/api/resource/)、[请求头说明](https://docs.nocobase.com/plugin-development/client/request)
- 角色配置涉及 roles、rolesUsers、rolesResources、rolesResourcesActions、rolesResourcesScopes 等系统表。角色名称创建成功并不等于数据权限已生效；必须用厂长账号实测读取成功、修改/管理拒绝，用副厂账号实测指定编辑动作，并检查匿名访问拒绝。[内置表说明](https://docs.nocobase.com/ops-management/migration-manager/built-in-tables)
- Collection 建模和角色资源动作应以启动后 OpenAPI Schema、实际启用插件及版本为准。本轮没有已启动 NocoBase 服务，因此未验收 collections/fields/roles 的创建 payload，不能将猜测 payload 作为可直接上线的配置。

## 本项目 V0.2.0 的实际选择

首版采用独立 Python + SQLite + HTTP 本机业务服务，延续用户已批准的页面结构，制作登录、事项台账、范围筛选、日报/周报导出与更新状态。**该首版未集成 NocoBase，也不是 NocoBase 部署交付。**

这是避免为本机试用先进行系统级环境变更的实施选择，不表示 NocoBase 不可用。后续需要正式内网或厂外多人长期访问时，可重新评估 NocoBase + PostgreSQL；迁移前保留稳定事项 ID、来源定位、人工确认与审计数据。
